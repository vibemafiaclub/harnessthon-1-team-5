# PRD — 동네반찬 정기배송

> 개발용 PRD ①. 하네스 개발·튜닝에 쓴다.
> 축: 커머스 / 모바일 웹 / **정보밀도 낮음** / 사진 중심 / 따뜻한 톤

---

## 1. 배경

1인·2인 가구가 동네 반찬가게에서 반찬을 사려면 매번 가게에 들러야 한다.
가게 입장에서는 그날 만든 양을 다 못 팔면 버린다.

주 1회 정기배송으로 양쪽 문제를 동시에 푼다. 가게는 수요를 미리 알고 만들고,
손님은 안 나가도 된다.

## 2. 대상 사용자

- **주 사용자**: 30~50대 1~2인 가구. 요리는 하지만 반찬까지 만들 여력은 없다.
  스마트폰으로 장을 보지만 앱 설치는 꺼린다 → **모바일 웹**.
- **부 사용자**: 반찬가게 사장(50~70대). 주문 목록만 확인하면 된다.

## 3. 해결하려는 문제

| # | 문제 | 지금은 어떻게 |
|---|---|---|
| P1 | 매주 무엇이 오는지 몰라 불안하다 | 전화로 물어봄 |
| P2 | 이번 주만 건너뛰고 싶다 | 전화로 취소 |
| P3 | 아이가 못 먹는 재료가 들어온다 | 매번 말해야 함 |
| P4 | 가게가 그날 만든 양을 예측 못 한다 | 감으로 |

## 4. 핵심 기능 (1차 범위)

- **이번 주 구성 미리보기** — 배송 3일 전에 무엇이 오는지 사진과 함께 보여준다 (P1)
- **한 주 건너뛰기** — 배송 2일 전까지 버튼 하나로 (P2)
- **못 먹는 재료 등록** — 가입 시 한 번, 이후 자동 제외 (P3)
- **가게용 주간 주문표** — 이번 주 총 수량만 (P4)
- 결제는 **월 정기결제** 1종. 단건 구매 없음.

1차 범위에서 **제외**: 리뷰, 별점, 검색, 장바구니, 쿠폰, 추천.
반찬 종류는 가게가 정하고 손님이 고르지 않는다 — 이게 이 서비스의 성격이다.

## 5. 필요한 화면

| 화면 | 무엇이 있어야 하나 |
|---|---|
| 이번 주 구성 | 반찬 사진 4~6개, 각 이름과 한 줄 설명, 배송일, "건너뛰기" 버튼 |
| 지난 주 기록 | 주차별 목록, 각 주에 뭐가 왔는지 |
| 내 정보 | 못 먹는 재료 목록, 배송지, 결제 수단, 구독 상태 |
| 가입 | 전화번호 인증 → 배송지 → 못 먹는 재료 → 결제 |
| 가게용 주문표 | 이번 주 반찬별 총 수량, 배송지 목록 |

빈 상태가 필요한 곳: 지난 주 기록(첫 주엔 없음), 못 먹는 재료(없을 수 있음).

## 6. 톤과 방향

동네 가게의 물성이 남아 있어야 한다. 반질반질한 이커머스가 아니다.
음식 사진이 주인공이고 UI는 물러나 있어야 한다.

싸구려로 보이면 안 된다 — 정기결제를 맡기는 서비스다.

## 7. 제약

- 모바일 웹 우선. 데스크톱은 같은 레이아웃을 가운데 정렬하는 수준.
- 사장님이 쓰는 화면은 글자가 커야 한다.
- 사진이 없는 반찬이 있을 수 있다. 그때도 화면이 무너지면 안 된다.

## 8. 성공 기준

- 가입한 사람의 60%가 3개월 이상 유지
- "이번 주 뭐 와요?" 문의 전화가 절반으로
