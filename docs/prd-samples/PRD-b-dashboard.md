# 콜드체인 온도 관제 — 제품 요구사항

> 개발용 PRD ②. 하네스 개발·튜닝에 쓴다.
> 축: 관제 대시보드 / 데스크톱 / **정보밀도 매우 높음** / 시계열 데이터 중심 / 기능적·차가운 톤
>
> ※ PRD-a와 **문서 구조를 일부러 다르게** 썼다. 하네스가 특정 PRD 서식에 과적합하지 않는지 보기 위해서다.

## 우리가 푸는 것

의약품·신선식품 콜드체인은 운송 중 온도가 규정 범위를 벗어나면 화물 전체를 폐기해야 한다.
지금은 도착 후 로거를 회수해서야 이탈을 안다. **이미 늦었다.**

실시간 온도를 받아서, 이탈이 **일어나는 중에** 관제 담당자가 개입하게 만든다.

## 누가 쓰나

24시간 3교대 관제실 담당자. 한 사람이 동시에 **80~200대**의 차량을 본다.
모니터는 27인치 2대. 교대 인수인계 시 5분 안에 현황을 파악해야 한다.

이 사람은 화면을 하루 8시간 본다. **예쁜 것보다 피로하지 않은 것이 중요하다.**

## 반드시 되어야 하는 것

1. 전체 차량의 상태를 **한 화면에서** 판단한다. 스크롤로 찾게 하지 않는다.
2. 이탈은 **3초 안에** 눈에 띈다. 소리와 색 둘 다 쓴다.
3. 한 차량을 클릭하면 **최근 24시간 온도 곡선**과 규정 범위가 겹쳐 보인다.
4. 이탈 발생 시 **조치 기록**을 남긴다 — 누가, 언제, 무엇을 했는지.
5. 교대 인수인계용 **요약**을 뽑는다.

## 상태 정의 (이게 화면의 뼈대다)

| 상태 | 조건 | 화면에서 |
|---|---|---|
| 정상 | 규정 범위 내 | 눈에 띄지 않아야 한다 |
| 주의 | 범위 경계 ±1℃ 이내 30분 지속 | 구분되되 시선을 뺏지 않는다 |
| 이탈 | 범위 벗어남 | **즉시 눈에 들어와야 한다** |
| 통신두절 | 15분간 수신 없음 | 이탈과 **구분**되어야 한다 |
| 조치중 | 담당자가 인지 처리함 | 이탈이지만 이미 잡힌 것 |

**정상이 대부분이다.** 200대 중 195대가 정상인 화면에서 5대를 찾는 문제다.

## 화면

- **관제 메인** — 전체 차량 그리드, 상태별 요약 카운트, 이탈 목록 우선 노출
- **차량 상세** — 온도 곡선(24h), 규정 범위 밴드, 위치, 화물 정보, 조치 이력
- **조치 입력** — 이탈 건에 대해 사유/조치/담당자 기록
- **교대 요약** — 지난 8시간 이탈 건수, 미조치 건, 진행 중 건
- **규정 관리** — 화물 유형별 온도 범위 설정

## 데이터 갱신

30초 폴링. 화면이 갱신될 때 담당자가 보던 위치를 잃으면 안 된다.

## 톤

관제실 조명이 어둡다. **다크 테마가 기본**이고 라이트는 없어도 된다.
색은 상태를 나타내는 데만 쓴다. 장식용 색을 쓰지 않는다.
빨강은 이탈에만 쓴다 — 다른 데 쓰면 빨강이 의미를 잃는다.

## 하지 말아야 할 것

- 애니메이션 전환. 30초마다 갱신되는 화면에서 전환 효과는 방해다.
- 카드 그림자와 둥근 모서리 남용. 밀도가 떨어진다.
- 아이콘만으로 상태 표시. 색각 이상 담당자가 있다 — **색 + 형태 + 텍스트** 세 겹.

## 성공 기준

- 이탈 인지까지 평균 3분 → **30초**
- 교대 인수인계 시간 15분 → 5분
- 폐기 화물 연 12건 → 3건 이하
