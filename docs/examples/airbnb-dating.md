# [디자인 과제] 마음에 드는 상대를 찾고 나를 보여주는 경험을 설계해주세요

안녕하세요. 아래 과제를 확인하고 결과물을 제출해주세요.

## 1. 배경

Airbnb를 만든 팀이 **소개팅 서비스**를 준비하고 있습니다.

숙소를 고를 때 사진과 후기를 보고 신뢰를 쌓았던 것처럼, 사람을 만날 때도 같은 경험을
주려고 합니다. 기존 소개팅 앱은 상대에 대해 알 수 있는 게 사진 몇 장뿐이라,
대부분의 사용자가 **무엇을 보고 판단해야 할지 모른 채** 넘기기만 반복합니다.

## 2. 기존 자산

현재 서비스의 디자인 파일을 함께 전달드립니다.

- Penpot 파일: 여러분 조의 **`작업`** 파일
- 읽을 대상: **`2-airbnb` Page** — 화면 5개가 들어 있습니다
  `Explore 1.1` 탐색 · `listing-details` 숙소 상세 · `Wishlist 2.1` 위시리스트 ·
  `Inbox 4.1` 메시지 · `Profile 5.1` 프로필

⚠️ 같은 파일에 **`1-daangn` Page**도 있습니다. 그건 **다른 과제의 기존 파일**이니
이 과제에서는 **`2-airbnb`만** 읽어주세요.

이 Page가 저희가 가진 전부입니다. 별도의 디자인 시스템 문서나 컴포넌트 정리본은 없습니다.

## 3. 핵심 유저 스토리

1. **가입을 마친 사용자로서**, 추천받은 상대를 한 명씩 보며 관심 여부를 표현하고 싶다.
   거리를 중요시하는 사용자도, 외모를 중요시하는 사용자도, 관심사를 중요시하는 사용자도 있습니다.
2. **상대에게 선택받고 싶은 사용자로서**, 내 프로필을 매력적으로 채우고 수정하고 싶다.
3. **신중한 사용자로서**, 공개되는 정보의 범위를 내가 통제하고 싶다.

## 4. 사용자들의 상황

- 추천은 **하루 10명**까지 제공됩니다. 다 보고 나면 다음 날까지 기다려야 합니다.
- 프로필 사진은 **최대 6장**까지 등록할 수 있습니다.
  6장을 다 채우는 사용자도, **한 장만 올리고 마는** 사용자도 많습니다.
- 가입 직후에는 **아직 아무것도 입력하지 않은** 상태로 프로필 편집에 들어옵니다.
- 닉네임이 이미 사용 중이거나 소개 문구가 너무 길어 **다시 입력해야 하는** 경우가 있습니다.
- 사진을 여러 장 올리면 저장에 **몇 초가 걸립니다.**

## 5. 만들어야 할 화면

**최소 2개**를 만들어주세요. 여유가 있다면 더 만드셔도 좋지만,
아래 두 개를 먼저 완성한 뒤에 진행해주세요.

### 5-1. 상대 탐색 `New/Discover`

**목적**: 추천된 상대를 한 명씩 보고, 관심 여부를 빠르게 표현한다.

**필수 요소**
- **상대 프로필 카드** — 사진이 화면의 주가 되도록. 이름·나이·거리·소개 문구
- 다음 카드가 뒤에 있음을 알 수 있는 표현
- **좋아요 / 패스** 액션
- 상세 프로필로 넘어가는 진입점

### 5-2. 프로필 편집 `New/ProfileEdit`

**목적**: 내 프로필을 채우고 공개 범위를 정한다.

**필수 요소**
- **사진 등록** — 여러 장, 순서 변경 가능
- **입력 항목** — 닉네임, 한 줄 소개, 직업, 관심사
- **공개 범위 설정** — 항목별 on/off
- 저장 액션

## 6. 조건

- **기존 디자인의 톤앤매너를 유지해주세요.** 정돈은 하되, 다른 제품처럼 보이면 안 됩니다.
- 새로 만드는 색·간격·타이포·컴포넌트는 **기존 화면에서 도출한 규칙**을 따라주세요.
- 이미지·아이콘·더미 텍스트 등 필요한 자산은 **직접 조달해주세요.**

## 7. 제출

- 신규 화면의 최상위 프레임 이름은 **`New/` 로 시작**해주세요.
  → `New/Discover`, `New/ProfileEdit`
- 신규 화면은 **본인 이름 Page**에 만들어주세요. (`2-airbnb`는 읽기 전용입니다)
- 완료 후 디스코드 제출 채널에 **파일 링크**를 남겨주세요.

## 이렇게 평가해요

### 디자인 완성도
사용성뿐 아니라 심미적 완성도를 봅니다. 익숙한 UI 패턴도 이 제품의 맥락에 맞게
다듬어 쓰는지, 시각적 디테일로 화면을 마무리하는지가 중요합니다.

### 라이브러리 재사용
색·간격·타이포를 토큰으로, 반복 요소를 컴포넌트로 정리하고 **실제로 그것을 써서**
화면을 만들었는지 봅니다. 같은 것을 복사해 붙였는지, 하나를 정의해 재사용했는지가 갈립니다.

### 구조와 네이밍
프레임 위계가 의미 단위로 정리되어 있는지, 각 요소의 이름이 그것이 무엇인지 말해주는지 봅니다.
`Frame 27`이 아니라 `ProfileCard`여야 합니다.

### Auto Layout
크기와 내용이 바뀌어도 무너지지 않는 구조인지 봅니다.

> 저희가 최종적으로 보는 것은 **보기 좋은 그림**이 아니라
> **AI 에이전트가 읽고 이어서 작업할 수 있는 데이터로서의 디자인**입니다.
