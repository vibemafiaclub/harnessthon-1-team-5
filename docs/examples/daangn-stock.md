# [디자인 과제] 관심종목을 담고 매수까지 가는 경험을 설계해주세요

안녕하세요. 아래 과제를 확인하고 결과물을 제출해주세요.

## 1. 배경

당근마켓을 만든 팀이 **증권 서비스**를 준비하고 있습니다.

주식을 처음 시작하는 사람이 대상입니다. 기존 증권 앱은 화면 하나에 숫자가 수십 개씩
들어가 있어서, 무엇을 봐야 할지 모르는 사람은 첫 화면에서 이탈합니다.
동네 이웃과 중고거래하듯 **부담 없고 익숙한 경험**으로 주식을 접하게 하는 것이 목표입니다.

## 2. 기존 자산

현재 서비스의 디자인 파일을 함께 전달드립니다.

- Penpot 파일: 여러분 조의 **`작업`** 파일
- 읽을 대상: **`1-daangn` Page** — 화면 5개가 들어 있습니다
  홈 피드 · 상품 상세 · 나의 당근(프로필·메뉴) · 채팅 목록 · 롱스크롤 화면

⚠️ 같은 파일에 **`2-airbnb` Page**도 있습니다. 그건 **다른 과제의 기존 파일**이니
이 과제에서는 **`1-daangn`만** 읽어주세요.

이 Page가 저희가 가진 전부입니다. 별도의 디자인 시스템 문서나 컴포넌트 정리본은 없습니다.

## 3. 핵심 유저 스토리

1. **투자를 처음 하는 사용자로서**, 관심 있는 종목을 모아두고 등락을 한눈에 확인하고 싶다.
2. **매수를 고민 중인 사용자로서**, 종목의 가격 흐름과 기본 정보를 보고 판단하고 싶다.
   어떤 사용자는 등락률을, 어떤 사용자는 내 수익률을, 어떤 사용자는 거래량을 먼저 봅니다.
3. **매수를 결정한 사용자로서**, 수량과 가격을 입력해 주문하고 그 결과를 확인하고 싶다.

## 4. 사용자들의 상황

- 관심종목은 **평균 12개**를 담습니다. 많게는 **200개**까지 담는 사용자도 있습니다.
- 가입 첫날이라 **아직 아무것도 담지 않은** 사용자가 매일 유입됩니다.
- 장 시작 직후에는 **시세가 아직 들어오지 않는** 몇 초가 있습니다.
- 주문을 넣었는데 **잔고가 모자라거나 장이 닫혀** 실패하는 경우가 있습니다.
- 하루에 한 번도 안 들어오는 사용자와, 장중에 수십 번 들어오는 사용자가 섞여 있습니다.

## 5. 만들어야 할 화면

**최소 2개**를 만들어주세요. 여유가 있다면 더 만드셔도 좋지만,
아래 두 개를 먼저 완성한 뒤에 진행해주세요.

### 5-1. 관심종목 `New/Watchlist`

**목적**: 사용자가 담아둔 종목의 현재가와 등락을 한 화면에서 훑는다.

**필수 요소**
- 종목 목록 — 종목명, 현재가, 등락률
- 상승/하락의 시각적 구분
- 정렬 또는 필터 진입점

### 5-2. 종목 상세 `New/StockDetail`

**목적**: 종목 하나를 판단하고, 그 자리에서 주문까지 끝낸다.

**필수 요소**
- **가격 차트** — 기간 전환(1일/1주/1개월 등) 포함
- 현재가와 등락 정보
- 종목 기본 정보
- **매수 / 매도 주문 진입** — 하단 고정 액션
- **주문 시트** — 수량·가격 입력, 예상 금액, 주문 확정
  (별도 화면이 아니라 이 화면 위에 올라오는 형태로 만들어주세요)

## 6. 조건

- **기존 디자인의 톤앤매너를 유지해주세요.** 정돈은 하되, 다른 제품처럼 보이면 안 됩니다.
- 새로 만드는 색·간격·타이포·컴포넌트는 **기존 화면에서 도출한 규칙**을 따라주세요.
- 이미지·아이콘·더미 텍스트 등 필요한 자산은 **직접 조달해주세요.**

## 7. 제출

- 신규 화면의 최상위 프레임 이름은 **`New/` 로 시작**해주세요.
  → `New/Watchlist`, `New/StockDetail`
- 신규 화면은 **본인 이름 Page**에 만들어주세요. (`1-daangn`은 읽기 전용입니다)
- 완료 후 디스코드 제출 채널에 **파일 링크**를 남겨주세요.

## 이렇게 평가해요

### 디자인 완성도
사용성뿐 아니라 심미적 완성도를 봅니다. 익숙한 UI 패턴도 이 제품의 맥락에 맞게
다듬어 쓰는지, 시각적 디테일로 화면을 마무리하는지가 중요합니다.

### 라이브러리 재사용
색·간격·타이포를 토큰으로, 반복 요소를 컴포넌트로 정리하고 **실제로 그것을 써서**
화면을 만들었는지 봅니다. 같은 것을 복사해 붙였는지, 하나를 정의해 재사용했는지가 갈립니다.

### 구조와 네이밍
프레임 위계가 의미 단위로 정리되어 있는지, 각 요소의 이름이 그것이 무엇인지 말해주는지 봅니다.
`Frame 27`이 아니라 `StockRow`여야 합니다.

### Auto Layout
크기와 내용이 바뀌어도 무너지지 않는 구조인지 봅니다.

> 저희가 최종적으로 보는 것은 **보기 좋은 그림**이 아니라
> **AI 에이전트가 읽고 이어서 작업할 수 있는 데이터로서의 디자인**입니다.
