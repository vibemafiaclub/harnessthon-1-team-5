# scaffold-harness — 확정된 중간단계 → 하네스 초안

설계 세션에서 팀이 정한 **중간단계 목록**을 받아, 실행 가능한 하네스 뼈대를 만든다.

만드는 것은 두 가지뿐이다.

| 산출물 | 경로 | 역할 |
|---|---|---|
| 진입점 오케스트레이터 | `.claude/skills/start/SKILL.md` | 단계 호출 순서 정의. **직접 저작하지 않는다** |
| 단계별 sub agent | `.claude/agents/stage-{n}-{slug}.md` | 각자 중간 산출물 1개 생성 |

> ⚠️ **이 skill은 조장이 실행한다.** `start/SKILL.md`는 공용 파일이라, 팀원이 각자
> 돌리면 서로의 설계를 덮어쓴다. 실행 전에 "조장 맞으신가요?"를 물어 확인한다.

---

## STEP 0 — 단계 목록을 확보한다 (게이트)

입력은 셋 중 하나다.

1. 사용자가 대화로 불러주는 단계 목록
2. `docs/stages.md` 같은 팀이 적어둔 설계 메모
3. 이미 있는 `.claude/agents/stage-*.md` (재생성·확장하는 경우)

**단계 목록이 없으면 만들지 않는다.** 추측해서 임의의 파이프라인을 찍어내지 않는다.
없으면 이렇게 되묻고 답을 기다린다:

> 확정된 중간단계를 순서대로 알려주세요. 각 단계마다 (1) 이름 (2) 무엇을 만드는지
> (3) 담당자 를 알려주시면 됩니다.

각 단계에 대해 아래가 채워질 때까지 질문한다. 비어 있는 채로 진행하지 않는다.

| 필드 | 없으면 |
|---|---|
| 단계 이름 | 되묻는다 |
| 이 단계의 **산출물 1개** | 되묻는다 ("이 단계가 끝나면 무슨 파일이 남나요?") |
| 읽어야 할 **입력** (PRD / 앞 단계 산출물) | 되묻는다 |
| 담당자 | 되묻는다 (`start`의 표에 기록되어야 한다) |

### 단계 분할 점검 — 아래에 걸리면 조장에게 알린다

- **산출물이 없는 단계**: 다음 단계가 읽을 게 없다. 합치거나 산출물을 정의하게 한다.
- **산출물이 2개 이상인 단계**: 쪼갤 후보다. 그대로 갈지 물어본다.
- **단계가 1개뿐**: 하네스가 아니라 스크립트다. 최소 3단계를 권한다.
- **단계가 8개 초과**: 오늘 안에 각 단계를 고도화할 시간이 없다. 우려를 알린다.

판단은 조장이 한다. 알리고 나서 조장이 그대로 가겠다고 하면 그대로 만든다.

---

## STEP 1 — 계약(입출력)을 확정한다

단계 간 통신은 **파일**로만 한다. 대화 맥락으로 넘기지 않는다.

- 모든 중간 산출물은 `docs/artifacts/{NN}-{slug}.md` 에 쓴다 (`NN` = 2자리 순번)
- 각 산출물은 **다음 단계가 읽고 바로 쓸 수 있는 형태**여야 한다.
  산문 요약이 아니라 표·목록·값으로 적는다.
- 앞 단계 산출물이 없으면 그 단계는 **즉시 중단하고 보고**한다. 추측해서 채우지 않는다.

의존관계를 표로 정리해 조장에게 보여주고, **병렬 가능 구간**을 표시해 확인받는다.
(입력이 겹치지 않는 단계는 병렬로 돌릴 수 있다.)

---

## STEP 2 — 🔴 Penpot 완성 보장 (건너뛰기 금지)

**이 skill의 계약은 "만들어진 하네스를 돌리면 Penpot에 디자인이 남는다"이다.**
문서만 쌓고 끝나는 파이프라인은 실패다. 그래서 팀이 준 단계 목록이 무엇이든,
아래 두 단계의 **존재를 강제한다.**

### (A) 저작 단계 — Penpot에 실제로 그리는 단계

팀 단계 중에 Penpot MCP를 호출해 도형을 만드는 단계가 **하나도 없으면**,
마지막에 `stage-{n}-author-penpot` 을 자동으로 추가한다. 추가했다면 조장에게 알린다.

> 단계 목록에 Penpot 저작 단계가 없어서 `stage-{n}-author-penpot`을 추가했습니다.
> 담당자를 정해주세요.

### (B) 검증 단계 — 진짜 남았는지 되읽는 단계

파이프라인 **맨 끝에 `stage-verify-penpot`을 항상 추가한다.** 예외 없다.
이 agent는 Penpot을 다시 읽어서 다음을 확인하고 `docs/artifacts/99-verify.md`에 적는다.

- 지정된 Page에 board/frame이 **1개 이상** 있는가
- PRD가 요구한 화면이 **전부** 있는가 (누락 목록을 적는다)
- 각 단계의 산출물 파일이 `docs/artifacts/`에 남아 있는가

**하나라도 실패하면 `start`는 완료를 선언하지 않는다.** 실패 항목을 담당 단계에
되돌려 재실행한다. 재실행 후에도 실패하면 사용자에게 무엇이 왜 비었는지 보고한다.

### 저작 단계에 반드시 박아 넣을 것 — 작업 Page 게이트

Penpot 파일은 팀원이 실시간으로 공유한다. **Page를 잘못 고르면 남의 작업 위에 그린다.**
저작·검증 agent 본문에 아래를 그대로 넣는다.

- Page 이름을 **인자로 받는다.** 받지 못했으면 저작을 시작하지 않고 사용자에게 묻는다.
- 기본값으로 첫 Page를 쓰지 않는다. 추측해서 고르지 않는다.
- `중간공유`·`최종제출`은 공용 Page다. 여기서 처음부터 저작하지 않는다.
  결과를 **옮겨 담는** 곳이다.
- `기존파일` Page는 **읽기 전용**이다. 과제의 기존 자산이 여기 들어 있다. 수정 금지.

---

## STEP 3 — sub agent 파일을 생성한다

`.claude/agents/stage-{n}-{slug}.md` 를 단계 수만큼 만든다. 템플릿:

```markdown
---
name: stage-{n}-{slug}
description: {한 문장. 이 단계가 무엇을 만드는지}
---

# {단계 이름}

## 입력 (이것만 읽는다)
- `docs/PRD.md`
- `docs/artifacts/{앞단계}.md`

## 출력 (이것만 쓴다)
- `docs/artifacts/{NN}-{slug}.md`

## 절차
1. 입력을 읽는다. 없으면 **즉시 중단하고 무엇이 없는지 보고한다.**
2. ...
3. 출력 파일을 쓴다.

## 출력 형식
{다음 단계가 파싱할 수 있는 구체적 형식 — 표/목록/키값}

## 금지
- 입력에 없는 값을 지어내지 않는다. 근거가 PRD/앞 단계에 있어야 한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
  "당근"·"에어비앤비" 같은 고유명사나 고정된 화면 개수를 코드/지침에 박지 않는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
```

**담당자 배정**: 각 파일 헤더 주석에 담당자를 적는다. 담당자만 그 파일을 고친다.
이미 존재하는 `stage-*.md`는 **덮어쓰지 않는다.** 팀원이 고도화해둔 내용이 날아간다.
이미 있으면 건너뛰고 "이미 존재해서 유지했습니다"라고 보고한다.

---

## STEP 4 — `start/SKILL.md`를 채운다

뼈대의 `<!-- 팀이 채울 것 -->` 주석을 실제 내용으로 교체한다.

- **단계 정의 표**: `# / 단계 / sub agent / 입력 / 출력 / 담당자 / 병렬 가능`
- **실행 순서**: 병렬 구간은 한 줄에 묶어 적는다
- 마지막 줄은 항상 `stage-verify-penpot` 호출 + 실패 시 재실행 규칙

`start`는 **오케스트레이션만** 한다. 직접 Penpot을 호출하거나 산출물을 쓰지 않는다.
각 sub agent를 부를 때 **입력 파일 경로·출력 파일 경로·작업 Page 이름**을 명시해 넘긴다.

---

## STEP 5 — 보고

생성 결과를 이렇게 요약한다.

- 만든 agent 목록 / 유지한 agent 목록
- 자동으로 추가한 단계 (저작·검증)와 그 이유
- 담당자 미정 단계
- 다음 액션: `/start` 로 1회 돌려보고 `docs/artifacts/99-verify.md` 확인

**초안이다.** 각 팀원이 자기 단계 agent를 고도화하는 것이 오늘의 본 작업이다.

## 금지

- 단계 목록 없이 임의 생성
- 기존 `stage-*.md` 덮어쓰기
- 검증 단계 생략
- `start`가 직접 저작하도록 쓰기
