# stage-reference — 레퍼런스와 원칙을 도출한다

## 계약

| 항목 | 내용 |
|---|---|
| **입력** | `docs/PRD.md` **이것만.** 다른 단계의 산출물도, Penpot도 읽지 않는다 |
| **출력** | `docs/artifacts/01-reference.md` |
| **done의 정의** | 아래 §완료검사 6항목을 **전부** 통과 |
| **허용 행동** | `ok` / `needs-more-info`(PRD에 없어서 못 정하는 것이 있을 때) / `failed` |
| **판단 규칙** | §도출 규칙. **PRD 내용을 하드코딩하지 않는다** — 어떤 PRD가 와도 같은 절차로 돈다 |

---

## 왜 이 단계가 있는가

디자인 품질은 값의 정밀함이 아니라 **의도가 얼마나 분명히 기술됐는가**로 결정된다.

> "**Adjectives describe a region. A specific reference describes a point.**"
> — DESIGN.md PHILOSOPHY

"모던하고 깔끔하고 신뢰감 있는"은 아무것도 지정하지 않는다. 모델은 그 형용사들이 그리는
영역의 **한가운데**를 만들고, 한가운데는 언제나 평범하다.

이 단계가 없으면 뒤의 모든 단계가 평범한 결과로 수렴한다.

---

## 도출 규칙

### 1) 구체적 레퍼런스 1문장

PRD에서 **대상 사용자 · 사용 맥락 · 정보 밀도 · 감정적 목표**를 읽고, 그 넷을 동시에 만족하는
**실재하는 사물/장소/시대**를 하나 지목한다.

문장은 아래 4개를 **전부** 포함해야 한다:

| 요소 | 예 |
|---|---|
| 시대 또는 연대 | "1970년대", "2010년대 초" |
| 매체 또는 사물 | "강의 유인물", "공항 안내판", "야장(野帳)" |
| 맥락·장소 | "오래된 대학의 세미나에서 배포되는", "선착장 대합실에 걸린" |
| 읽는 사람 | "대학원생과 연구 엔지니어가 읽는" |

**형용사만으로 이루어진 문장은 실패다.**

> ⚠️ 위 예시는 **형식을 보이기 위한 것이지 답이 아니다.** PRD가 무엇이든 이 예시를 쓰지 마라.
> 예시가 답으로 굳으면 그것이 곧 과적합이다 — 모든 결과물이 같은 레퍼런스로 수렴한다.

레퍼런스는 PRD에서 **도출**하는 것이지 취향으로 고르는 것이 아니다.
왜 그 레퍼런스인지 PRD의 어느 문장에서 왔는지 `derived_from`에 적는다.

### 2) 원칙표 — 4열

레퍼런스에서 **가져올 것**과 **가져오지 않을 것**을 같이 쓴다.

| 열 | 무엇을 쓰나 |
|---|---|
| 참고할 요소 | 레퍼런스의 구체적 특징 (관찰 가능한 것) |
| 추출한 원칙 | 그 특징이 **왜** 그런지, 우리에게 옮길 수 있는 규칙 형태로 |
| 적용할 화면 | PRD의 화면 목록 중 어디에 |
| **모방하지 않을 부분** | 레퍼런스에는 있지만 우리는 안 쓸 것 + **왜 안 쓰는지** |

마지막 열이 핵심이다. 이게 없으면 레퍼런스를 통째로 베끼게 된다.

### 3) Do's and Don'ts

**Don't 항목은 레퍼런스나 원칙표에서 파생돼야 한다.** 일반론("접근성을 지키자")은 쓰지 않는다.

> "A model knows what a lecture handout is, and it knows what a lecture handout **is not**...
> **Naming the object names them.**"

구체적 레퍼런스가 있으면 부정 제약이 **자동으로 따라온다.** 그래서 Don't를 길게 나열할 필요가 없다.

> "**A long rambling list is often a sign the description was too vague to carry them.**"

**Don't가 12개를 넘으면 레퍼런스를 다시 좁혀라.** 목록이 길다는 것은 레퍼런스가 약하다는 신호다.

### 4) 화면 목록

PRD에서 화면을 추출한다. 각 화면에 **빈 상태·에러 상태가 필요한지** 표시한다.
PRD가 명시하지 않았어도 목록·검색·입력이 있으면 빈 상태가 필요하다.

### 5) 대표 화면 지정

원칙표의 "적용할 화면" 열에서 **가장 많이 등장한 화면**을 대표 화면으로 지정한다.
동점이면 아래 순으로 판정:

1. 컴포넌트 종류가 가장 많은 화면
2. 정보 위계가 3단 이상인 화면
3. PRD가 가장 많이 언급한 화면

대표 화면은 `stage-compose`가 pilot 모드에서 **먼저 1장만** 만들어 방향을 확인하는 데 쓴다.

|---|---|---|---|---|

## 화면 목록

- **Don't** ...   ← 각 항목 끝에 (원칙 #N에서) 를 붙여 출처를 밝힌다
- **Do** ...

- ...   ← 있으면 여기 모으고 `needs-more-info`로 반환한다. 추측해서 채우지 않는다

## 완료 검사 (스스로 돌린다)

| # | 검사 | 실패 시 |
|---|---|---|
| 1 | 레퍼런스 문장에 시대·매체·맥락·독자가 전부 있는가 | 다시 쓴다 |
| 2 | 레퍼런스가 형용사 나열이 아닌가 | 다시 쓴다 |
| 3 | `derived_from`이 PRD의 실제 문장을 가리키는가 | 다시 쓴다 |
| 4 | 원칙표의 "모방하지 않을 부분"이 **전 행에** 채워졌는가 | 빈 행을 채운다 |
| 5 | **Don't가 12개 이하**이고 전부 출처(원칙 #N)가 붙었는가 | 12개 초과면 **레퍼런스를 좁혀 다시 시작** |
| 6 | 화면 목록의 각 화면에 필요한 상태가 표시됐는가 | 채운다 |

## 금지

- PRD에 없는 기능·화면을 **지어내지 않는다.** 모르면 `needs-more-info`.
- 특정 브랜드의 디자인 시스템 이름을 레퍼런스로 쓰지 않는다
  ("Material Design처럼" ❌ — 그건 매체가 아니라 이미 만들어진 답이다).
- 색상 hex·폰트 이름·px 값을 여기서 정하지 않는다. **이 단계는 의도만 정한다.**
  값은 `stage-designmd`가 정한다.
