# ⑤ 검증 — 되읽어서 확인한다

**만들었다고 말하는 것과 남아 있는 것은 다르다.** 이 단계는 Penpot을 다시 읽는다.

## 입력 (이것만 읽는다)
- `docs/artifacts/01-screens.md` (채점표로 쓴다)
- `docs/artifacts/02-policy.md` (예산 배정표)
- Penpot **지정 Page** (읽기. 전환하지 않는다)

## 출력 (이것만 쓴다)
- `docs/artifacts/99-verify.md`

## 🔴 Page 규칙
- 검사할 Page 이름을 **인자로 받는다.** 없으면 묻고 멈춘다.
- **읽기만 할 때는 Page를 전환하지 않는다.** 전환하면 남이 보는 화면도 바뀐다.

## A. 존재 검사

| 검사 | 통과 조건 |
|---|---|
| 보드 존재 | 지정 Page에 board/frame 1개 이상 |
| 화면 누락 | `01-screens.md`의 모든 화면ID가 보드 이름으로 존재 |
| 상태 화면 | 빈/검색없음/오류/완료/권한 중 목록에 있던 것이 전부 존재 |
| 산출물 | `docs/artifacts/`에 각 단계 파일이 남아 있음 |

누락은 **화면ID 목록으로** 적는다. "일부 누락" 같은 요약을 쓰지 않는다.

## B. 컬러 예산 검사 (계산으로 한다)

Penpot에는 그레이스케일 미리보기가 없다. `develop/scripts/color-audit.js`를
`use_figma`로 실행해 화면별 수치를 받는다.

| 지표 | 통과 조건 | 깨졌을 때 |
|---|---|---|
| `solidPrimaryButtonCount` | **== 1** | 주 행동 1개만 남기고 `btn/secondary`로 강등 |
| `primaryElementCount` | **≤ 5** | 재배치 |
| `primaryAreaRatio` | **≤ 0.10** | 대면적을 `primaryWeak`/`surface`로 교체 |
| `neutralStepsUsed` | **== 5** | 컬러로 구조를 대신한 것. `surface`/`border` 도입 |

## C. 조형 검사

| 검사 | 통과 조건 |
|---|---|
| 텍스트 클리핑 | `growType === "fixed"`인 텍스트 0개. 보이는 글자가 잘리지 않음 |
| 정렬 편차 | 같은 역할 요소(카드·행)의 x좌표·좌우 패딩이 서로 동일 |
| 아이콘 일관 | `icon/*`이 동일 그리드·굵기. 1톤 아이콘이 남아 있지 않음 |
| 로고 | `logo/*`가 원본 컬러이거나, 전부 `textSub` 단색으로 통일됨 (섞이면 실패) |
| 빈 상태 구성 | 각 상태 화면에 **일러스트 + 문구 + 버튼 1개**가 전부 있음 |
| 자리표시 문구 | `Lorem`·"텍스트"·"제목 1" 등이 0건 |
| 에셋 출처 | 반입한 로고·사진이 `develop/assets/_sources.json`에 기록됨 |

## D. 렌더 확인
- 화면마다 `export_shape`로 PNG를 찍는다.
- **빈 영역이 나오면 재-export 한 번** 후 판단한다. 레이아웃 안정 전에 찍히면 빈다.

## 출력 형식

```markdown
# 검증 결과

- 작업 Page: {이름}
- 판정: 통과 | 실패
- 실패 항목 수: {N}

## A. 존재
| 검사 | 결과 | 누락 화면ID |

## B. 컬러 예산
| 화면ID | solidPrimary | primaryCount | primaryAreaRatio | neutralSteps | 판정 |

## C. 조형
| 검사 | 결과 | 대상 |

## 되돌릴 단계
| 실패 항목 | 담당 단계 | 조치 |
```

## 실패 처리

- **실패 항목이 하나라도 있으면 완료를 선언하지 않는다.**
- 해당 단계에 되돌려 재실행한다. 어느 단계인지 표에 명시한다.
- 재실행 후에도 실패하면 **무엇이 왜 비었는지** 사용자에게 보고한다. 조용히 넘기지 않는다.

## 금지
- 검사 없이 통과 판정
- Page 전환
- 도형 수정 — 이 단계는 **읽기만** 한다. 고치는 것은 담당 단계의 일이다.
