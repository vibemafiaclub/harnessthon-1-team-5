# ⑥ 이관 — 공용 Page로 옮겨 담는다

**심사 대상은 `최종제출` Page다.** 이 단계가 없으면 저작해놓고 제출이 안 된다.
동시에 **공용 Page라 잘못 쓰면 남의 결과를 지운다.** 그래서 게이트가 많다.

## 🔴 실행 게이트 — 하나라도 못 넘으면 시작하지 않는다

1. **출발 Page 이름**을 인자로 받았는가 (내 작업 Page)
2. **대상 Page 이름**을 인자로 받았는가 (`중간공유` 또는 `최종제출`)
3. 대상 Page에 **이미 내용이 있는가** → 있으면 **사용자에게 알리고 답을 받기 전에 진행하지 않는다**
4. `docs/artifacts/99-verify.md`가 **통과**인가 → 실패면 이관하지 않는다

**기본값으로 Page를 고르지 않는다. 추측하지 않는다.**
`기존파일` Page는 읽기 전용이며 이관 대상이 될 수 없다.

## 입력 (이것만 읽는다)
- `docs/artifacts/01-screens.md` (옮길 화면ID 목록)
- `docs/artifacts/99-verify.md` (통과 여부)
- 인자: 출발 Page / 대상 Page / (선택) 옮길 화면ID 범위

## 출력
- 대상 Page에 복제된 화면들
- `docs/artifacts/06-publish.md` — 옮긴 화면ID, 대상 Page, 건너뛴 것과 이유

## 절차

### STEP 1. 확인
- `99-verify.md` 판정이 **통과**인지 본다. 실패면 **중단하고 보고한다.**
  실패한 화면을 공용 Page에 올리지 않는다.
- 대상 Page의 기존 내용을 읽어 **무엇이 있는지 사용자에게 먼저 보고한다.**

### STEP 2. Page 고정
```js
// 읽을 때와 쓸 때 각각 별도 호출로 전환한다.
// openPage() 는 다음 호출까지 유지되지 않는다.
const src = penpot.currentFile.pages.find(p => p.name === SRC_PAGE);
penpot.openPage(src);
```
**전환한 그 호출 안에서 새 Page 노드를 만지면 죽는다.** 전환은 별도 호출로 먼저 한다.

### STEP 3. 복제
- 출발 Page에서 화면ID에 해당하는 보드를 찾아 `clone()` 한다
- **별도 호출로** 대상 Page를 연 뒤, 복제본을 그 Page에 배치한다
- 배치는 `01-screens.md`의 화면ID 순서대로 격자로 놓는다
- 이름은 **화면ID 그대로 유지**한다. 바꾸지 않는다

> ⚠️ Page 간 이동 API는 검증되지 않았다. `clone()` 후 대상 Page에 붙이는 방식이
> 안 되면 **한 화면으로 먼저 시험하고** 결과를 보고한 뒤 진행한다.
> 전체를 한 번에 시도하지 않는다.

### STEP 4. 확인
- 대상 Page에서 `export_shape`로 몇 장 찍어 실제로 옮겨졌는지 본다
- 비어 나오면 **재-export 한 번** 후 판단한다
- 옮긴 목록을 `06-publish.md`에 적는다

## 금지
- **공용 Page에서 처음부터 저작하기.** 여기는 옮겨 담는 곳이다
- 대상 Page의 기존 내용을 확인 없이 지우거나 덮기
- `99-verify.md`가 실패인데 이관하기
- 화면 이름 변경 (검증·심사가 화면ID로 찾는다)
- 인자 없이 기본 Page로 진행하기
