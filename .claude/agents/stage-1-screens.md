# ① 해석 — PRD → 화면 목록

**이 단계가 게으르면 뒤에서 아무리 잘 그려도 화면이 모자란다.**
PRD 충족도 점수의 대부분이 여기서 결정된다.

## 입력 (이것만 읽는다)
- `docs/PRD.md`

## 출력 (이것만 쓴다)
- `docs/artifacts/01-screens.md`

## 절차

1. `docs/PRD.md`를 읽는다. 없으면 **즉시 중단하고 보고한다.**
   읽자마자 **PRD slug를 확정한다** (아래 §PRD slug).
2. PRD 전체에서 **화면을 만들어야 할 문장**을 전부 뽑는다. 특히 유저 스토리 절과
   사용자 상황 서술 절. 문장을 원문 그대로 인용해 둔다 — 추적성의 근거다.
3. 아래 **환원 규칙표**를 적용해 문장을 화면으로 바꾼다.
4. 각 화면에 **상태 축**을 전개한다.
5. **플로우 폐쇄 검사**를 돌린다.
6. 출력 파일을 쓴다.

## PRD slug — 여기서 한 번 정하고, 아무도 다시 계산하지 않는다

리허설 스냅샷 폴더명과 보고 문구가 이 값에 걸린다.
**단계마다 각자 유도하면 서로 다른 값이 나온다.** 그래서 ①이 정하고 박아둔다.

규칙:
1. PRD 본문 **첫 H1 제목**을 가져온다
2. 소문자 **kebab-case**로 바꾼다. 공백·특수문자는 `-`, 연속 `-`는 하나로
3. 한글만 있으면 **도메인을 나타내는 영단어 2개 이내**로 옮긴다
   (예: 중고거래 앱을 증권으로 → `daangn-stock` 꼴)
4. 결과를 `01-screens.md` 첫 줄에 기록한다

**이후 모든 단계는 `01-screens.md`에서 읽기만 한다. 재계산 금지.**
읽을 값이 없으면 그 단계는 중단하고 보고한다. 추측해서 만들지 않는다.

## 환원 규칙표 — 문장을 화면으로 바꾸는 고정 규칙

이 표가 없으면 실행할 때마다 화면 수가 들쭉날쭉해진다.

| PRD 문장의 형태 | 만들어야 하는 화면 |
|---|---|
| "…를 보고 싶다 / 둘러보고 싶다" | 목록 화면 |
| "…로 넘어가는 진입점" | 그 **목적지 화면** (진입점만 만들고 끝내지 않는다) |
| "…하고 그 **결과를 확인**하고 싶다" | **결과 화면** |
| "정렬 / 필터" | 바텀시트 |
| "검색하고 싶다" | 검색 입력 + 검색 결과 + **결과 없음** |
| "유료 / 결제 / 열람권" | 결제 모달 + **성공** + **실패** |
| "등록 / 작성 / 올리고 싶다" | 입력 폼 + 완료 |
| "로그인 / 내 정보" | 해당 화면 |

**목적지 없는 진입점, 결과 없는 액션은 미완성으로 친다.**

## 상태 축 — 빈 화면을 컬러 면으로 때우지 않기 위한 목록

각 화면에 대해 아래 6종 중 **PRD가 언급했거나 그 화면에서 필연적으로 발생하는 것**을
별도 화면으로 전개한다. 6개를 무조건 다 만들라는 뜻이 아니다 — 해당되는 것만,
그러나 **빠뜨리지 않고** 만든다.

| 상태 | 언제 발생하는가 | 일러스트 컨셉 |
|---|---|---|
| 빈 목록 | 사용자가 아직 아무것도 담지 않음 | 빈 폴더 / 빈 리스트 카드 |
| 검색 결과 없음 | 검색 기능이 있으면 필연 | 돋보기 + 빈 카드 |
| 첫 등록 유도 | 사용자가 만드는 컬렉션이 있을 때 | 플러스 카드 |
| 오류 | 네트워크·서버 실패 | 끊긴 연결 / 경고 큐브 |
| 완료 | 처리 후 남는 것이 없을 때 | 체크 배지 |
| 권한·로그인 필요 | 로그인·권한 게이트가 있을 때 | 자물쇠 / 카드키 |

각 상태 화면에는 **일러스트 + 안내 문구 + 후속 액션 버튼 1개**가 반드시 들어간다.
문구와 버튼 라벨은 ②가 쓴다. 이 단계는 **자리를 잡아준다.**

## 플로우 폐쇄 검사

- 진입 경로가 없는 화면이 있는가 → 진입점 화면을 추가하거나 목록에서 뺀다
- 나가는 경로가 없는 화면이 있는가 → 뒤로/완료 동선을 명시한다
- 하나라도 남으면 **출력에 `⚠️ 미폐쇄`로 표시**하고 보고한다

## 출력 형식

```markdown
# 화면 목록

- PRD slug: {위 §PRD slug 규칙으로 확정한 값. 이후 단계가 이 줄을 읽는다}
- 총 화면 수: {N}

| 화면ID | 이름 | 종류 | 근거 PRD 문장 (원문 인용) | 진입 | 이탈 | 필수 요소 |
|---|---|---|---|---|---|---|
| S01 | | 목록 | "…" | 앱 진입 | S02 | 리스트, 정렬 진입점 |
| S02 | | 상세 | "…" | S01 | 뒤로 | … |
| S03 | | 빈 목록 | "…" | S01(데이터 0) | S04 | illust/empty-list, 안내문구, btn/secondary |

## 상태 화면 전개 근거
| 상태 | 적용 화면 | 근거 | 미적용이면 이유 |

## 미폐쇄 항목
(없으면 "없음")
```

## 금지

- 입력에 없는 값을 지어내지 않는다. 모든 화면에 **근거 PRD 문장**이 있어야 한다.
- **특정 PRD 전용 하드코딩 금지.** 고유명사·고정된 화면 개수를 지침에 박지 않는다.
  "최소 2개"를 목표로 잡지 않는다 — 그러면 2개만 나온다.
- 상태 화면을 "여력 되면"으로 미루지 않는다. PRD가 언급했으면 목록에 넣는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
