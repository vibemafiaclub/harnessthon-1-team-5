# _base/voice — 보이스 & 톤 추출 절차

> ⚠️ 절차 문서. 이 PRD의 writing 가이드는 `docs/artifacts/03-design.md` §보이스.
>
> **특정 서비스의 문구를 여기 적지 않는다.** 심사용 PRD는 미공개다.
> 여기 적는 것은 "어떻게 뽑을 것인가"뿐이다.

## 1. 수집 — `기존파일` Page에서 텍스트를 전부 긁는다

```js
// 텍스트 노드 수집 (읽기만. Page 전환하지 않는다)
const page = penpot.currentFile.pages.find(p => p.name === "기존파일");
// page 하위를 순회해 type === "text" 노드의 characters 를 모은다
```

역할별로 나눠 담는다. 톤은 역할마다 다르다.

| 역할 | 예 |
|---|---|
| 버튼 라벨 | 행동 문구 |
| 제목 | 화면·섹션 이름 |
| 안내문 | 빈 상태·설명 |
| 에러 | 실패 메시지 |
| 메타 | 시간·수치 표기 |

기존 파일에 텍스트가 없으면 **PRD 본문 문장의 어미를 그대로 따른다.**

## 2. 분석 — 아래 축으로 패턴을 뽑는다

| 축 | 확인할 것 |
|---|---|
| 존댓말 | 해요체 / 합니다체 / 반말 |
| 어미 | "~해요" "~하세요" "~하기" 명사형 |
| 길이 | 버튼 라벨 몇 글자, 안내문 몇 줄 |
| 인칭 | 사용자를 뭐라 부르는가 (생략 / 님 / 회원) |
| 이모지 | 쓰는가, 어디에 |
| 숫자 표기 | 단위 붙임·띄움, 천단위 |

**빈도로 정한다.** 예외 1~2개를 규칙으로 삼지 않는다.

## 3. 이식 — 톤은 유지하고 명사만 갈아끼운다

PRD는 보통 **기존 서비스의 톤을 새 도메인에 옮기는 것**을 요구한다.

- 어조·어미·길이는 **그대로 유지**한다
- 도메인 명사만 PRD의 어휘로 바꾼다
- 기존 서비스에 없던 상황(결제·실패 등)은 **같은 어미 규칙으로 새로 쓴다**

## 4. 상태 화면 문구 — 사과하지 않고 다음 행동을 준다

빈 상태·오류 화면의 문구가 완성도를 크게 좌우한다.

- **사과("죄송합니다")로 시작하지 않는다.** 다음 행동을 제시한다
- 기본 패턴: `"{대상}이 없어요"` + `"{다음 행동}해 보세요"`
- 안내문 아래 **버튼 1개**만 둔다. 빈 상태에서 선택지를 늘리지 않는다
- 실패 원인을 기술 용어로 쓰지 않는다 (서버·네트워크·에러코드)

## 5. 출력 형식 — `docs/artifacts/03-design.md` §보이스

```markdown
## 톤 규칙
| 축 | 값 | 근거 (기존파일에서 관찰된 예) |
|---|---|---|
| 존댓말 | 해요체 | "…" 외 N건 |
| 어미 | ~해요 / 명사형 | … |

## 역할별 규칙
| 역할 | 규칙 | 길이 |
|---|---|---|
| 버튼 라벨 | 동사 명령형 | N자 이내 |

## 금지 표현
- (관찰되지 않은 어투)

## 상태 문구 템플릿
| 상태 | 문구 | 버튼 라벨 |
```

②가 이 파일을 읽어 화면별 실제 문구를 쓴다.
**③은 규칙까지, ②는 문장까지.** 경계를 넘지 않는다.

## 금지

- 근거 없는 톤 규칙 (관찰 예를 함께 적지 않은 것)
- 특정 서비스 고유명사를 절차 문서에 기입
- 화면별 실제 문구를 여기서 확정하는 것 (그건 ②의 일이다)
