# _base/iconography — 로고·아이콘·일러스트 규칙

> 출처: 디자이너 피드백 리포트 v1.1 §2 §3
> 진단: **각 로고가 단색 처리됨.** 원인은 브랜드 마크와 UI 아이콘을 같은 규칙으로 취급.
>
> ⚠️ 절차 문서. 값은 `docs/artifacts/03-design.md` §아이콘.

## 0. 셋을 구분한다 — 규칙이 서로 다르다

| 종류 | 정체 | 색 규칙 |
|---|---|---|
| **브랜드 로고** | 남의 자산 | **원본 컬러 유지.** 임의 단색화 금지 |
| **UI 아이콘** | 우리 자산 | 2톤(듀오톤) |
| **일러스트/3D 아이콘** | 빈 영역을 채우는 것 | 뉴트럴 베이스 + accent 1곳 |

**이 셋을 한 규칙으로 처리하면 로고가 죽는다.** 이번 회차의 c 문제가 정확히 이것이다.

## 1. 브랜드 로고

- **원본 브랜드 컬러 그대로**가 기본이다.
- 단색화가 불가피하면(대비 문제, 파트너사 나열 등) **전부 동일 규칙으로** 통일한다:
  `textSub` 100% 그레이. 일부만 원본색으로 남기지 않는다.
- 정렬은 **폭이 아니라 시각 무게 기준**이다. 가로형·정방형이 섞이면
  **높이 기준 그리드 + 좌우 여백 24px 이상**으로 맞춘다.
- clear space = 로고 높이의 **0.5배**.

### 수급 우선순위 (위에서 답이 나오면 아래로 안 내려간다)
1. `기존파일` Page에 이미 있는 마크 — **최우선**
2. 공식 브랜드 리소스·프레스킷
3. 라이선스가 명시된 공식 SVG 아카이브
4. 없으면 **넣지 않는다.** 검색 결과 이미지를 임의로 쓰지 않는다

반입한 에셋은 `develop/assets/_sources.json`에 기록한다.
**기록이 없는 에셋은 화면에 넣지 않는다.**

```json
[{ "file": "", "company": "", "source_url": "", "fetched_at": "", "license": "", "usage_note": "" }]
```

> 실제 기업 로고를 "파트너사/고객사"로 표기하려면 그 관계가 사실이어야 한다.
> PRD에 근거가 없으면 **가상 브랜드명으로 대체**한다. 사실과 다른 표기는 그 자체가 리스크다.

## 2. UI 아이콘

- **단색 1톤을 쓰지 않는다. 2톤(듀오톤)으로 간다.**
  - 주 획: `text`
  - 보조 면: `secondary` 20% 틴트 (`fillOpacity: 0.2`)
- **24px 그리드**, 획 굵기·라운드 통일. 서로 다른 아이콘 세트를 섞지 않는다.
- 상태 아이콘(성공/경고/오류)만 semantic 컬러를 쓴다.
- 아이콘은 전부 **컴포넌트로** 만든다. 화면마다 다시 그리지 않는다.

## 3. 일러스트 / 3D 아이콘

**빈 영역을 primary 컬러 면으로 때우지 않는다.** 이번 회차의 b 문제다.
컬러 면 대신 전용 일러스트를 놓는다. 어디에 놓는지는 `01-screens.md`가 정한다.

### 생성 경로 — 이 하네스에는 이미지 생성 모델이 없다

| 경로 | 언제 | 방법 |
|---|---|---|
| **A. 벡터 조립 (주 경로)** | 항상 가능 | `/empty-state-illust` 스킬이 Penpot 도형으로 조립 |
| B. 외부 생성본 반입 | 팀이 미리 뽑아둔 PNG가 있을 때 | `penpot.uploadMediaUrl(name, url)` |
| C. 실사진 | 인물·매장 등 | `uploadMediaUrl`. 초상권·저작권 확인된 것만 |

경로 B의 원본 프롬프트는 `develop/assets/_prompts.md`에 보관한다(재생성용).

### 공통 조형 규칙 — A·B 어느 쪽이든 지킨다
세트 일관성이 무너지면 완성도 점수가 즉시 깎인다.

- 단일 주제 1개. 장식 추가 금지. 귀엽게 만들지 않는다(신뢰감 우선)
- 단순 기하 도형, 둥근 모서리, 부드러운 볼륨
- **3/4 아이소메트릭풍 각도를 세트 전체에서 동일하게**
- 광원은 **좌상단 하나**, 오브젝트 아래 접지 그림자 1개
- 베이스는 흰색·연회색, **accent는 한 부분에만 (아이콘 면적의 20% 미만)**
- 배경 투명. 카드 배경이 필요하면 `surface`로 처리
- 오브젝트 중앙 정렬 + 넉넉한 여백

### 캐릭터
`기존파일` Page에 브랜드 캐릭터가 **이미 있을 때만** 쓴다.
없으면 **새로 만들지 않는다.** 3D 오브젝트 아이콘으로 통일한다.

## 4. 네이밍 규약 — 검증이 이 이름으로 검사한다

이름을 안 지키면 `color-audit.js`가 버튼·아이콘을 구분하지 못한다.
**컴포넌트 이름은 나중에 못 바꾼다**(플러그인이 멈춘다). 처음에 확정한다.

| 프리픽스 | 대상 |
|---|---|
| `btn/primary` `btn/secondary` `btn/outline` | 버튼 |
| `icon/{name}` | UI 아이콘 |
| `logo/{company}` | 브랜드 로고 |
| `illust/{state}` | 빈 상태 일러스트 |
| `card/{name}` `field/{name}` | 그 외 컴포넌트 |
