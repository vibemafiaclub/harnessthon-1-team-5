# _base/layout — 그리드·여백 산출 절차

> ⚠️ 절차 문서. 이 PRD의 값은 `docs/artifacts/03-design.md` §레이아웃.
>
> **레이아웃·정렬은 채점 4항목 중 하나다.** 그리고 계산으로 검증 가능한 유일한 항목이다.

## 1. 화면 규격

기준 프레임 **375 × 812** (모바일). PRD가 다른 폼팩터를 요구하면 그것을 따르고
`docs/artifacts/03-design.md` §레이아웃에 근거를 적는다.

## 2. 그리드

- 좌우 패딩은 **전 화면 동일**하다. 화면마다 다르면 정렬이 무너진다
- 콘텐츠 폭 = 375 − (좌우 패딩 × 2)
- 세로 리듬은 `SPACE` 토큰 배수로만 쌓는다. 눈대중으로 조정하지 않는다

### 뽑는 방법
`기존파일`에서 실제 좌우 패딩 분포를 수집해 **최빈값 1개**를 고른다.
값이 갈리면 가장 많이 쓰인 쪽으로 통일한다.

## 3. 화면 골격

```
┌─────────────────┐
│ appbar          │  고정 높이
├─────────────────┤
│                 │
│ content         │  스크롤 영역
│                 │
├─────────────────┤
│ tabbar 또는 CTA  │  고정 높이
└─────────────────┘
```

- 골격 상수(앱바 높이·하단 높이)의 **값은 ②가 `02-policy.md`에 확정**한다.
  ③은 그 재료가 되는 간격 단계까지만 만든다
- 상단·하단 고정 요소는 **모든 화면에서 같은 높이**를 쓴다

## 4. 🔴 Penpot 레이아웃 함정 — 여기서 정렬이 깨진다

| 함정 | 대응 |
|---|---|
| `layoutGrow` Spacer가 폭 1로 되돌아간다 | 하단 고정 요소는 **Spacer 높이를 계산해 명시** |
| `primaryAxisSizingMode` 등 figma 사이징이 안 먹는다 | `node.horizontalSizing = "fix" \| "auto"` (penpot 쪽) |
| 비-오토레이아웃 프레임은 `appendChild`가 자식을 안 옮긴다 | 붙인 뒤 `c.x = parent.x + dx; c.y = parent.y + dy` |
| hug(자동 폭) 칸은 텍스트를 갈아끼워도 위치가 안 따라온다 | 가변 텍스트 칸은 **고정 폭 + 텍스트 정렬** |
| hHug 프레임 안 텍스트가 아래가 잘린 채 굳는다 | 화면을 다 만든 뒤 `growType === "auto-height"` 텍스트를 **전부 `resize`로 재계산** |
| 고정 폭 텍스트를 `growType="fixed"`로 두면 글자가 잘린다 | `growType = "auto-height"` |

**마지막 두 개는 저작 끝난 뒤 일괄 처리한다.** 개별 화면에서 잡으면 놓친다.

## 5. 캔버스 배치 — 심사자가 파일을 열었을 때의 첫인상

- 화면 보드를 **격자로 일정 간격** 배열한다 (가로 간격·세로 간격 각각 상수)
- 배열 순서는 `01-screens.md`의 화면ID 순서를 따른다
- 보드 이름 = **화면ID**. ⑤ 검증이 이 이름으로 찾는다
- 상태 화면(빈/오류/완료)은 원본 화면 **바로 옆이나 아래**에 둔다. 흩어놓지 않는다

## 6. 정렬 자가 검수

⑤가 검사하지만, ④가 먼저 본다.

- 같은 역할 요소(카드·행)의 **x좌표가 전부 같은가**
- 좌우 패딩이 화면마다 같은가
- 세로 간격이 `SPACE` 배수인가 (4px 배수를 벗어난 값이 있는가)
- 고정 요소(앱바·하단)의 높이가 화면마다 같은가

하나라도 어긋나면 **눈으로는 못 찾는다.** 좌표를 뽑아 비교한다.

## 금지

- 화면마다 다른 좌우 패딩
- 4px 배수를 벗어난 간격
- 눈대중 위치 조정 (좌표를 값으로 지정한다)
- 골격 상수의 **값**을 여기서 확정하는 것 (그건 ②의 일이다)
