# Design

디자인 시스템 문서 모음. 각 파일은 300줄 이내로 유지한다.

## 🔴 특정 PRD 전용으로 쓰지 않는다

**심사용 PRD는 미공개다.** 당근 색·당근 문구를 이 디렉토리에 상수로 박으면
심사 당일 그 값들이 전부 오답이 된다.

그래서 이 디렉토리는 두 층으로 나눈다.

```
design/
├── _base/         ← PRD 무관. "어떻게 뽑을 것인가"(절차)만 적는다. 사람이 쓴다
├── daangn/        ← 당근 PRD로 돌렸을 때 뽑혀 나온 값
├── airbnb/        ← Airbnb PRD로 돌렸을 때 뽑혀 나온 값
└── final/         ← 최종 심사용 PRD 결과
```

- `_base/`에 **값**이 들어가면 안 된다. 절차와 스키마만 들어간다.
- `daangn/`·`airbnb/`는 `_base/`의 절차가 실제로 돌아가는지 검증하는 **대조군**이다.
  둘의 결과가 서로 달라야 정상이다. 같으면 절차가 PRD를 안 읽고 있다는 뜻이다.
- 하네스는 `_base/`를 읽고, 결과를 `{prd-slug}/`에 쓴다.

`policy/`와 같은 구조다. 둘을 같은 PRD slug로 맞춘다.

## 포함 문서

`_base/`와 각 PRD 디렉토리 모두 같은 파일 세트를 갖는다.

| 파일 | `_base/` (절차) | `{prd-slug}/` (값) |
|---|---|---|
| `token.md` | 색·타이포·간격을 **무엇에서 어떻게 뽑는가** | 뽑혀 나온 팔레트·스케일 |
| `component.md` | 화면 목록에서 컴포넌트를 **환원하는 규칙** | 이 PRD의 컴포넌트 목록과 규격 |
| `iconography.md` | 아이콘 스타일·사이즈 **결정 기준** | 이 PRD의 아이콘 세트 |
| `voice.md` | 문구 톤을 **추출하는 절차** | 이 PRD의 writing 가이드 |
| `layout.md` | 그리드·여백 **산출 규칙** | 이 PRD의 그리드·여백 값 |

## 값을 어디서 뽑는가

우선순위 순이다. 위에서 답이 나오면 아래로 안 내려간다.

1. **`기존파일` Page** — 과제의 기존 자산. 색·타이포·컴포넌트가 여기 있다.
   `penpot.currentFile.pages`로 읽는다. **읽기 전용, 수정 금지.**
2. **PRD 본문** — 3절(유저 스토리)·4절(사용자들의 상황)에 톤과 상황이 적혀 있다.
3. **위 둘에 근거가 없을 때만** 일반 모바일 UI 관례로 채우고,
   그 사실을 `{prd-slug}/` 문서에 "근거 없음 — 관례로 채움"이라고 명시한다.

## voice.md 작성 절차 (`_base/`에 적을 것)

1. `기존파일` Page의 텍스트 노드를 전부 수집한다 (버튼·안내문·에러·빈 상태)
2. 패턴을 분석한다 — 어조, 존댓말 여부, 문장 길이, 이모지 사용, 명사형/서술형
3. PRD가 정의한 **새 도메인**에 그 패턴을 이식한다
   (예: 중고거래 톤 → 증권 도메인. 톤은 유지, 명사만 갈아끼운다)
4. writing 가이드라인으로 정리해 `{prd-slug}/voice.md`에 쓴다

기존 파일에 텍스트가 없으면 PRD 문장의 어미를 그대로 따른다.

## 토큰 규칙

- **토큰은 JS 상수 객체로 들고 다닌다.** `figma.variables.*`는 성공 응답만 오고
  실제 토큰이 거의 안 남는다 (AGENTS.md 함정 표 1번). Penpot 토큰 셋과
  동기화하려 하지 말 것.
- 저작 스크립트는 이 상수 객체를 import해서 쓴다. 화면마다 색을 다시 적지 않는다.
- `fills`는 **penpot 형식** `{fillColor:"#RRGGBB", fillOpacity:1}`을 쓴다.
  figma 형식은 인스턴스 오버라이드에서 막힌다.

## 규칙

- 각 파일 **300줄 이내**
- 하드코딩된 값 대신 토큰 이름을 참조한다
- `_base/`를 고칠 때는 당근/airbnb **둘 다** 다시 돌려서 결과가 갈라지는지 본다
