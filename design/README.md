# Design

디자인 시스템 문서 모음. 각 파일은 300줄 이내로 유지한다.

## 🔴 특정 PRD 전용으로 쓰지 않는다

**심사용 PRD는 미공개다.** 당근 색·당근 문구를 이 디렉토리에 상수로 박으면
심사 당일 그 값들이 전부 오답이 된다.

그래서 **절차와 값을 분리한다.**

```
design/
├── _base/         ← PRD 무관. "어떻게 뽑을 것인가"(절차)만. 사람이 쓴다
└── {prd-slug}/    ← 리허설 결과 스냅샷. 손으로 복사해 커밋한다 (선택)
```

- **`_base/`에 값이 들어가면 안 된다.** 절차와 스키마만 들어간다.
- **하네스가 만든 값은 `docs/artifacts/03-design.md` 에 쓴다.** 이 디렉토리가 아니다.
  (`decision/001` 0번 결정 — 하네스는 `docs/artifacts/`만 쓴다)
- `{prd-slug}/`는 **하네스가 쓰지 않는다.** 당근·Airbnb 리허설 결과를 비교용으로
  남기고 싶을 때 사람이 `03-design.md`를 복사해 넣는 곳이다.
  둘의 결과가 서로 달라야 정상이다. 같으면 절차가 PRD를 안 읽고 있다는 뜻이다.

## `_base/` 문서 5종

| 파일 | 무엇을 규정하는가 |
|---|---|
| `token.md` | Color 역할 슬롯·사용 예산, Typography 5~6단, Spacing 4px, Radius 3단 |
| `component.md` | 화면 목록에서 컴포넌트를 환원하는 규칙, 이름 확정·인스턴스 제약 |
| `iconography.md` | 브랜드 로고 / UI 아이콘 / 일러스트 3분리, 네이밍 규약 |
| `voice.md` | 문구 톤 수집·분석·이식 절차 |
| `layout.md` | 그리드·골격·Penpot 레이아웃 함정·정렬 검수 |

## 값을 어디서 뽑는가

우선순위 순이다. 위에서 답이 나오면 아래로 안 내려간다.

1. **`기존파일` Page** — 과제의 기존 자산. `penpot.currentFile.pages`로 읽는다. **수정 금지**
2. **PRD 본문** — 3절(유저 스토리)·4절(사용자들의 상황)에 톤과 상황이 적혀 있다
3. **위 둘에 근거가 없을 때만** 일반 모바일 UI 관례로 채우고,
   `03-design.md`에 "근거 없음 — 관례로 채움"이라고 명시한다

외부에서 구한 디자인 문서가 있어도 **`기존파일`과 충돌하면 기존파일이 이긴다.**

## ③ 단계의 출력 계약

| 산출물 | 경로 | 용도 |
|---|---|---|
| 사람이 읽는 값 표 | `docs/artifacts/03-design.md` | ②·④가 읽는다 |
| 저작용 JS 상수 | `develop/scripts/tokens.js` | ④가 import한다 |

**두 벌을 다 내야 한다.** 문서만 내면 ④가 색을 못 쓴다.
`tokens.js`는 `docs/artifacts/`에 못 두는 유일한 예외다 — import 되어야 하기 때문이다.

## 규칙

- 각 파일 **300줄 이내**
- 하드코딩된 값 대신 토큰 이름을 참조한다
- **`figma.variables.*`를 쓰지 않는다.** 성공 응답만 오고 토큰이 거의 안 남는다
- `_base/`를 고칠 때는 당근/Airbnb **둘 다** 다시 돌려서 결과가 갈라지는지 본다
